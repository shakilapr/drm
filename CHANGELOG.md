### Changed

- Runtime algorithm docs revised after cross-document audit: consumer lifecycle gains `Closing` state with atomic close-vs-acquire hazard arbitration (REQ-CORE-005); reclamation authority moved from process inspection to endpoint registration locks — process identity is diagnostic only (REQ-CORE-036/037/056/057); hard-RT publish path performs zero inspection syscalls, reclamation deferred via `reclaim_requested` (REQ-CORE-095); fork contract: inherited DRM objects invalid in child, atfork sanitization, `O_CLOEXEC`, no `LOCK_UN` from duplicates (REQ-CORE-099); OS object names generated from deployment ID + topic handle, never canonical topic strings (REQ-CORE-088); POSIX stale-object classification before exact-size attach — crash before `ftruncate` is recoverable (REQ-CORE-098); observed epoch persisted across read calls (REQ-CORE-096); bounded read primitives `try_next`/`try_latest` with `WouldRetry` (REQ-CORE-097); one hazard acquisition primitive for all four read APIs; `hazard_protected_on_sc` specified as single-pass `O(R+H)` validity rule; single physical `publish_busy` owner in the CCB; Windows `Init` recovery reinitializes in place under the publisher lock; session-scoped persistence restated as opportunistic.
- Router algorithm docs revised after falsification review: per-link scheduler spans all transports (REQ-ROUTE-034), route-scoped egress admission (REQ-ROUTE-035), independent fan-out branches with reliable-branch session failure (REQ-ROUTE-036/037), generated stream receive bounds (REQ-ROUTE-038), defined shaping charge + burst ≥ max frame (REQ-ROUTE-039), serial blocking bound (REQ-ROUTE-040), u64 stream epochs (REQ-ROUTE-011), bounded strict priority + DRR anti-starvation (REQ-ROUTE-020), DRM-boundary isolation wording.
- Serial/MCU: serial CRC covers e2e trailer (I-SR3), CRC guarantees restated (bursts ≤ 32 bits), MCU zero-heap enforced by preventive build barriers (REQ-CORE-087), COBS boundary golden vectors.
- Qualification: evidence-classed traceability + mutation audit (REQ-QAL-006), three soak gates (REQ-QAL-005), per-platform reproducible builds (REQ-QAL-001), fuzz/sanitizer resolution gate (REQ-QAL-007).
- Binding/ABI algorithm docs revised after boundary review: C ABI gains opaque `drm_context`, copy publish + zero-copy write-loan (`write_acquire`/`commit`/`abort`, channel-publish loan form), full read surface (`borrow_latest/next`, `copy_latest/next` with exact GAP out-params); lengths validated against structural bound before any Rust slice (REQ-BIND-005); `drm_status` fixed `int32_t` with explicit values, no C enum (REQ-BIND-017); fail-stop FFI — panic terminates the node, `Internal` status removed (REQ-BIND-020); one-way ABI compatibility policy (REQ-BIND-018); per-handle thread-safety: publisher endpoint concurrent-safe (`Busy` loser), consumer endpoint single-borrower (REQ-BIND-002); consumer multiplicity declared as manifest `borrowers = N` with activation-time record/hazard reservation, `H = Σ borrowers + diagnostic range` (REQ-BIND-010); Python owned-reads-only — buffer protocol/memoryview/NumPy views removed, hazard-free after every call (REQ-BIND-015); C++ `Borrow` is the owning accessor (no view/span escape), shared types layer vs node facade split (REQ-BIND-012); Rust guards `!Send + !Sync` via `PhantomData` with trybuild proofs (REQ-BIND-016); Python threading model: `Send + Sync` pyclass, per-`Topic` native lock, free-threaded CPython (REQ-BIND-022); out-params zeroed on every failure path; close-with-borrow aligned to `Busy`/`Closing` (I-CR4).
