## Notes

- No architecture divergence: the slice implements pinned invariants
  (record-replay I-RC1..I-RC6, deployment-identity I-DP2, serial-mcu
  I-SR2..I-SR7); no ADR landed.
- Carry-over: the record disk stage + MCAP framing (M15W3 scope, quarantined)
  landed in this tranche as the replay prerequisite — `REPLAY_FAITHFUL` needs
  recorded bytes to read back. `drm-record` remains an ops crate depending only
  on `drm-types` + `drm-core` (`#![forbid(unsafe_code)]`); the MCAP reader/writer
  is from scratch (`zstd` only for optional chunk compression).
- Replay clock semantics: `recv_mono_ns` drives scheduling, `recv_wall_ns` is
  indexing-only, and source timestamps are replayed verbatim (documented split).
- MCU interop: the Arm cross-build + host parity + zero-forbidden-heap audit run
  in `mcu-cross.yml`; the authoring host lacks the pinned `arm-none-eabi`
  toolchain, so the local suite carries the host cross-decode matrix and parity
  legs. Gate M16W4 evidence is archived here and in
  [metrics-m15.md](../metrics/metrics-m15.md).
