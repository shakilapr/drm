## Notes

- No architecture divergence: the implementation follows the pre-existing
  [spatial-core.md](../algorithms/spatial/spatial-core.md) and
  [spatial-queries.md](../algorithms/spatial/spatial-queries.md) pseudocode; no
  ADR. The `SimReplay` clock semantics are tested with injected mapping
  fixtures; `Global` (`PTP`/`GNSS`) sources are likewise injected, so no live
  PTP/GNSS source is required.
- `drm-spatial` stays layer `runtime` and depends only on `drm-types`
  (codebase.md 2.1); plan execution uses a fixed `[Transform3; MAX_PLAN_DEPTH]`
  stack with zero heap allocation (`I-Q15`).
- Regression permanence (AGENTS #14): the M19W2 `clocks`/`cache` suites become
  blocking gates.
- Carry-over: geodetic boundary precision ⇒ M19W3 (E2); forest queries ⇒ M19W3
  (E1); coherent `latest`/`at`/`predict`/`delayed_view` ⇒ M20.
