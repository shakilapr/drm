## Notes

- No architecture divergence: the implementation follows the pre-existing
  [spatial-queries.md](../algorithms/spatial/spatial-queries.md) pseudocode and
  data-structure sketches (`ReparentMode`, `reparent`, time-scoped plans). No
  ADR.
- Atomicity: `QueryEngine` is single-writer (`&mut self`); `SpaceForest::begin`
  stages mutations on a clone and `TreeTxn::commit` replaces the whole forest in
  one step, so a reader between begin and commit sees the pre-tree, never a
  partial one (`I-Q10`). The reparent plan-version install and the forest swap
  happen with no observable intermediate in the single-writer engine.
- Discontinuities are marked per jumped local edge: `reparent` captures the
  object's dynamic edge before the relink and flags its retained sample at `t₁`
  (`I-Q7`/`I-Q9`); Preserve World keeps the anchor trajectory continuous.
- Carry-over / risk: the compiled-plan fold composes path segments in path order
  (`e0 ∘ e1 ∘ …`), which for multi-edge chains with non-commuting rotations
  differs from textbook `SE(3)` collapse order (`world_to_camera =
  world_to_base ∘ base_to_camera`). M20W1's translation-only fixtures never
  disambiguated this. The reparent oracle models the compiled-plan fold; the
  composition-order question is carried to the M20W3/M20W4 review (E1/E2) for a
  possible ADR.
- Regression permanence (AGENTS #14): the M20W1 `queries` suite and the M20W2
  `reparent` suite become blocking gates.
