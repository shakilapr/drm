## M13W4 crash-recovery matrix (criterion 3)

The crash matrix closes criterion 3 on the Windows runner. A publisher process
is killed and restarted 50 times (subset of the 100× Linux loop) over real
`LockFileEx` authority and a pagefile section kept alive by a live consumer
mapping; the reader-kill matrix proves reclamation against real Win32 process
identity (signaled + creation time) at every borrow stage. Both rows are green
in the cross-OS manifest and re-run under the permanent nightly gates.

| Case | Invariant | Test | Result |
|---|---|---|---|
| Publisher killed + restarted 50×: kernel lock release, exactly-once epoch advance, preserved floor, consumer observes each epoch | `I-W3`, `I-L2`, `I-L3`, `I-L4`, `I-L6` | `channel::lifecycle::tests::windows::win_lifecycle_crash_x50` (Windows runner) | PASS |

## Notes

- No architecture divergence: the crash matrix, reclamation matrix, interop
  harness, serial adapter, and link-cut isolation implement pinned invariants
  (publisher-lifecycle.md `I-L2`/`I-L3`/`I-L4`/`I-L6`, exhaustion-reclamation.md
  `I-E5`, windows-backends.md `I-W3`/`I-W5`, router-core.md
  `I-RT1`/`I-RT4`/`I-RT5`/`I-RT6`/`I-RT11`/`I-RT34`, serial-mcu.md
  `I-SR1`..`I-SR7`, deployment-identity.md namespaces), so no ADR landed.
- The OS labels in an interop cell select each endpoint's deployment namespace;
  the simulation fallback runs both endpoints on one host. The physical
  dual-VM/lab runner is wired by [phase-31-runbook.md](phase-31-runbook.md) at
  M14W1; physical rows not booked carry to the M14W2 fix window.
- [serial-mcu.md](../algorithms/router/serial-mcu.md) was finalized at M14W1
  (Phase 32): COBS is the binding escape choice and the frame-limit/CRC tables
  absorb the M02W3/M05W3/M06W1/M13W1 drafts. No normative statement changed, so
  no ADR landed.
