## Transport / language cells (seeded M03W1, full matrix M14W1)

Every `{linux,windows} × {c,cpp,rust,python} × {udp,tcp,serial}` cell must
eventually cross a real link. This 24-cell table is the **gate-blocking core
matrix**; the machine-readable source is `xtask/src/cross_os.rs`
(`INTEROP_CORE_LANG_PAIRS`, `interop_core_matrix`) and the generated table is
`target/interop/matrix-report.txt`. Status: `R` runner present; `-` tracked
(`Scheduled`, Phase 32/33 bindings).

| OS × language | udp | tcp | serial (host-loopback) |
|---|---|---|---|
| linux × c | - | - | - |
| linux × cpp | - | - | - |
| linux × rust | R | R | R |
| linux × python | - | - | - |
| windows × c | - | - | - |
| windows × cpp | - | - | - |
| windows × rust | R | R | R |
| windows × python | - | - | - |

- Rust UDP: `cargo test -p drm-router --lib udp`; `cargo run -p drm-router --example udp_pair` (10k loopback exchanges).
- Rust TCP: `cargo test -p drm-router --lib transport::tcp` (length-framed records, reconnect session scope).
- Rust serial: `cargo test -p drm-router --lib transport::serial` (bounded COBS + CRC32C codec, `serial_loopback_x10k` socketpair exchange on unix); the interop-cell serial link is a cross-platform in-process host-loopback of the same codec.
- Serial route integration (M13W2-E3): `cargo test -p drm-router serial_route` — the serial link enters the transport registry as a best-effort stream, and a sample crosses the full router path (egress filter → COBS/CRC32C encode → byte link → decode → native deposit).
- C/C++/Python cells over UDP/TCP/serial land with the Phase 32/33 bindings work (`serial-mcu.md`, `bindings/c-abi-surface.md`); they are tracked, not gate-blocking (work-plan M14W1-E4-T1).

## Cross-OS interop matrix (defined M13W2-E1, full matrix M14W1-E4)

The parameterized `{publisher_os, consumer_os} × {C, C++, Rust, Python} ×
{udp, tcp, serial}` cell runner lives in `xtask/src/cross_os.rs`
(`interop_matrix`); `cargo xtask test --cross-os --transport <udp|tcp|serial>`
executes every green cell on the current host over loopback (the documented
two-netns simulation fallback when a second host is unavailable) and archives
per-cell evidence (bytes + timing) under `target/interop/`, plus the full cell
table at `target/interop/matrix-report.txt`. Each endpoint runs under a
`deployment-identity.md` namespace derived from its OS/language labels.
Windows↔Linux cells re-run on the physical dual-VM/lab runner in the M14 matrix
(`docs/gates/phase-31.md` M14W1 section + runbook). The matrix is split by gate
role: the 24 same-language `{os}×{lang}×{transport}` cells are **core**
(gate-blocking); mixed-language pairs are **tracked**.

| Cell family | Direction | UDP | TCP | Serial |
|---|---|---|---|---|
| Rust ↔ Rust | windows→linux, linux→windows | green (sim fallback) | green (sim fallback) | green (codec host-loopback) |
| C ↔ C | windows→linux, linux→windows | tracked (Phase 32/33 bindings) | tracked | tracked |
| C++ ↔ C++ | windows→linux, linux→windows | tracked | tracked | tracked |
| Python ↔ Python | windows→linux, linux→windows | tracked | tracked | tracked |
| mixed-language pairs | both | tracked | tracked | tracked |

an explicit port note tracked on the port board while a platform fixture is
scheduled. The manifest is the single source of truth in `xtask/src/cross_os.rs`
(`SUBSET`); `cargo xtask test --cross-os` executes every green row on the current
host (Windows-only rows are `cfg`-gated and no-op elsewhere), so the nightly
Windows job and the local smoke never diverge. `cargo xtask test --cross-os
--full` runs the whole manifest `CONFORMANCE_RUNS = 2` times with run 2 required
green. `PORT_GAPS_CLOSED = 1` iff no row is silently missing: every scheduled row
